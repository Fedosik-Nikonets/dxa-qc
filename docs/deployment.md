# Руководство по развёртыванию

Как собрать образ, перенести его на машину без интернета, запустить
пакетную обработку и сервис с веб-интерфейсом и проверить, что всё работает.
Пользоваться сервисом — `docs/user_guide.md`.

## 1. Что нужно

* Docker 20+ (рекомендуется 24+) на Linux или macOS; на машине сборки —
  доступ к Docker Hub и PyPI, на рабочей машине сеть не нужна.
* CPU x86_64 или arm64; GPU не используется.
* Память: 1 ГБ минимум, 2 ГБ рекомендуется. Пиковая память процесса на
  обучающем наборе (499 файлов) — 242 МБ с overlay-серией, 225 МБ без неё.
* Диск: образ, входные данные и около 0.3 МБ на снимок под overlay-серию.

Скорость: около 0.1 с на исследование в среднем, с overlay-серией — 0.3 с;
самое долгое в стресс-тесте — 0.6 с при лимите ТЗ 2.7 в 3 минуты.

## 2. Сборка образа

```bash
./build.sh                               # под архитектуру этой машины
PLATFORM=linux/amd64 ./build.sh --save   # под x86_64 и в файл dxa-qc_<версия>.tar.gz
```

Что происходит:

* базовый образ `python:3.12.7-slim-bookworm` закреплён по sha256;
* зависимости из `docker/requirements-runtime.txt` — все версии, включая
  транзитивные, закреплены, ставятся только из готовых колёс, затем
  `pip check`;
* при сборке проверяется, что все три модели загружаются (`models/`), что
  создаётся приложение FastAPI и что в процесс не попали библиотеки обучения
  (torch, scikit-learn, pandas);
* после сборки контейнер запускается с `--network none` и печатает
  `health` — версию и загруженные модели.

## 3. Перенос на машину без интернета

```bash
docker load < dxa-qc_1.1.0.tar.gz
docker run --rm --network none dxa-qc:1.1.0 health
```

`health` должен показать `"loaded": true` у всех трёх моделей (`artifact`,
`rotation`, `quality_score`) и их sha256 — по ним видно, какие именно файлы моделей внутри.

## 4. Пакетная обработка

```bash
./run.sh <каталог или zip с исследованиями> <каталог для результатов>
```

Контейнер запускается без сети (`--network none`), вход монтируется только
на чтение, результаты принадлежат запустившему пользователю. В каталоге
результатов — `result.xlsx`, `overlays.zip`, `diagnostics.csv`.

Без `run.sh` — то же напрямую:

```bash
docker run --rm --network none \
  -v /путь/к/исследованиям:/data/input:ro -v /путь/к/результатам:/data/output \
  dxa-qc:1.1.0 batch --input /data/input --output /data/output/result.xlsx \
  --diagnostics /data/output/diagnostics.csv --overlays /data/output/overlays.zip
```

Ключи `batch`: `--overlay-format dicom|png|both` (что класть в
`overlays.zip`), `--region-lang code` (коды областей вместо русских
названий), `--limit N`, `--quiet`. Выход `.csv` вместо `.xlsx` — по
расширению `--output`.

Архив на входе годится как есть, в том числе архив организатора с именами в
cp866; обёртки вроде `НД_для_обучения/Исследования/` снимаются
автоматически. Небезопасные пути в архиве (`../`, абсолютные) отвергаются.

## 5. Сервис: API и веб-интерфейс

```bash
./run.sh --serve [порт]          # по умолчанию 8000
```

* `http://localhost:8000/` — веб-интерфейс;
* `http://localhost:8000/docs` — описание API (Swagger);
* `GET /health` — проверка живости для мониторинга.

`run.sh --serve` публикует порт только на `127.0.0.1`: сервис доступен с
этой машины. Чтобы открыть его в локальной сети медицинской организации:

```bash
docker run -d --name dxa-qc --restart unless-stopped -p 8000:8000 dxa-qc:1.1.0 serve
```

У сервиса нет авторизации и TLS: в сеть его можно выпускать только внутри
защищённого контура, а лучше — за обратным прокси организации (nginx и
т. п.) с авторизацией и HTTPS. Сам сервис никуда не обращается; сеть в
контейнере нужна только для публикации порта.

Запросы обрабатываются по одному (блокировка на прогон): конвейер
загружает ядро целиком, параллельные прогоны только делили бы его.

## 6. Настройки

| переменная | по умолчанию | что задаёт |
|---|---|---|
| `PORT` | 8000 | порт сервиса внутри контейнера |
| `DXA_QC_JOBS` | `<временный каталог>/dxa-qc-jobs` | где веб-интерфейс хранит результаты пяти последних обработок; смонтируйте том, если их нужно пережить перезапуск контейнера |
| `DXA_QC_MAX_UNZIP_BYTES` | 20 ГиБ | предел распакованного объёма архива |
| `DXA_QC_MAX_UNZIP_FILES` | 200 000 | предел числа файлов в архиве |

Пример: `docker run -e DXA_QC_JOBS=/jobs -v /srv/dxa-jobs:/jobs -p 8000:8000 dxa-qc:1.1.0 serve`.

## 7. Проверка после установки

1. `docker run --rm --network none dxa-qc:1.1.0 health` — все три модели загружены.
2. `./run.sh "Для теста.zip" out/` — три строки `Success` в `out/result.xlsx`,
   шесть файлов в `out/overlays.zip` (PNG и DICOM на каждый снимок).
3. Для сервиса — открыть `/`, загрузить тот же архив, открыть overlay любой
   строки.

## 8. Обновление моделей

Модели — три маленьких файла в `models/`: `artifact_tophat_v1.npz` (порог
детектора артефактов), `rotation_profile_v1.json` (границы правила
ротации) и `quality_score_v1.json` (крутизна правил для балла
`quality_score`). Как их получить заново — `docs/training.md`. Новый файл кладётся в
`models/`, образ пересобирается `./build.sh`; `health` покажет новый sha256.
Файл, посчитанный для другой версии признаков, модуль отвергает (поле
`feature_version`). Сборка образа не пройдёт, если хоть одна модель не
загружается, поэтому в готовый образ такой файл не попадёт. Вне образа
без файла или с несовместимым файлом модели соответствующая проверка
пропускается (`"loaded": false` в `/health`); сборка образа отдельно
проверяет наличие и совместимость всех штатных моделей.

## 9. Неполадки

| симптом | причина | что делать |
|---|---|---|
| `нужен Docker` | Docker не установлен или не в PATH | установить Docker |
| `exec format error` при запуске | образ собран под другую архитектуру | пересобрать с `PLATFORM=linux/amd64` или `linux/arm64` |
| `"loaded": false` у модели | в образе нет файла модели или он от другой версии признаков | пересобрать образ из репозитория как есть |
| `run.sh`: «нет входа» | неверный путь | путь к каталогу или zip-архиву |
| код возврата 2, «архив не распакован» | небезопасные пути или превышен предел | проверить архив; при необходимости поднять `DXA_QC_MAX_UNZIP_*` |
| в веб-интерфейсе «Сервис недоступен» | контейнер остановлен или порт не опубликован | `docker ps`, перезапустить `./run.sh --serve` |
