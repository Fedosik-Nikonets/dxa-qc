# HTTP API, веб-интерфейс и командная строка

[← README](../README.md) · [Карта документации](README.md)

Три способа запустить один и тот же конвейер `batch.run`: HTTP API, веб-страница
и командная строка. Таблицы, которые они выдают, совпадают построчно.

## HTTP API

`./run.sh --serve` поднимает сервис на `http://localhost:8000`: по корневому
адресу — веб-интерфейс (ниже), интерактивная документация API — `/docs`.

| метод | путь | вход | выход |
|---|---|---|---|
| GET | `/health` | — | статус, версия, какие модели загружены (артефакты, ротация, балл) и их sha256 |
| POST | `/batch` | zip-архив с исследованиями (поле `file`); параметры `format=xlsx\|csv`, `overlays=true\|false`, `overlay_format=both\|dicom\|png`, `region_lang=ru\|code` | файл таблицы; с `overlays=true` — zip с `result.<format>` и `overlays.zip` |
| POST | `/predict` | файлы одного исследования (поле `files`: DICOM или zip), параметр `study` | JSON: строки таблицы, итоговый `quality_class` и `quality_score` исследования |
| GET | `/` | — | веб-интерфейс |
| POST | `/ui/jobs` | zip или DICOM-файлы одного исследования (поле `files`); `overlays=true\|false` | JSON задания: строки таблицы, сводка, список файлов |
| GET | `/ui/jobs/{job}/files/{name}` | `result.xlsx`, `result.csv`, `overlays.zip` | файл задания |
| GET | `/ui/jobs/{job}/overlay` | `path` — `path_to_study`, `kind=png\|dcm` | overlay одного файла: PNG или DICOM Secondary Capture |

```bash
curl -F file=@НД_для_обучения.zip "http://localhost:8000/batch?overlays=true" -o result.zip
curl -F files=@CR000000.dcm -F files=@CR000001.dcm "http://localhost:8000/predict?study=S1"
```

Ошибки входа — ответ 400 с текстом причины (не архив, небезопасные пути в
архиве, превышен размер), ошибки параметров — 422. Ошибка на отдельном
файле ответа не ломает: как и в CLI, это строка `Failure` в таблице. API
— тонкая оболочка над тем же `batch.run`, что и командная строка: таблицы
совпадают построчно (тест `test_service.py`).

## Веб-интерфейс (ТЗ 2.6)

Открыть `http://localhost:8000/` после `./run.sh --serve`. Загрузка zip-архива
с исследованиями (хоть весь набор организатора) или DICOM-файлов одного
исследования перетаскиванием → пакетная обработка тем же конвейером, что у
CLI и `/batch` → на странице:

* сводка: исследования, файлы, сколько исследований и изображений с
  нарушениями, ошибки чтения, время на исследование;
* таблица по исследованиям с вердиктом исследования, фильтрами «с
  нарушениями / норма / ошибки чтения», по типу нарушения и поиском;
* просмотр overlay выбранного снимка с расшифровкой нарушений и
  скачиванием его DICOM Secondary Capture;
* скачивание `result.xlsx`, `result.csv` и `overlays.zip`.

Страница — один файл [`src/dxa_qc/web/index.html`](../src/dxa_qc/web/index.html) без внешних ресурсов:
работает в контейнере без сети. Данные из архивов выводятся только как
текст (никакого `innerHTML`). Входные файлы удаляются сразу после
обработки, хранятся результаты пяти последних заданий (каталог —
`DXA_QC_JOBS`, по умолчанию во временной папке). Светлая и тёмная тема,
вёрстка работает и на экране телефона.

## Командная строка без контейнера

```bash
python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
pip install -e . --no-deps          # чтобы работала команда ниже без PYTHONPATH

python -m dxa_qc.batch --input <каталог или zip> --output result.xlsx
python -m dxa_qc.service --port 8000            # API
```

Без установки пакета то же самое запускается как
`PYTHONPATH=src python -m dxa_qc.batch ...`.

Полезные ключи:

| ключ | что делает |
|---|---|
| `--diagnostics FILE.csv` | служебные колонки (углы, отступы, пороги) для разбора ошибок |
| `--overlays FILE.zip` | overlay-серия (ТЗ 2.6, 2.7) на каждый файл: DICOM Secondary Capture в исследовании исходника и PNG |
| `--overlay-format dicom\|png\|both` | что класть в архив overlay (по умолчанию `both`) |
| `--region-lang code` | короткие коды областей вместо русских названий |
| `--limit N` | обработать только первые N файлов |
| `--quiet` | без прогресса в stderr |

Выход — `.xlsx` или `.csv` по расширению. Запись детерминирована: два
прогона на одних данных дают побайтово одинаковый файл, кроме колонки
времени обработки.
