# Руководство пользователя

[← README](../README.md) · [Карта документации](README.md)

DXA QC проверяет качество денситометрических исследований поясничного
отдела позвоночника и проксимального отдела бедра (ТЗ 2.3) и показывает, по
какому измерению принято каждое решение. Руководство — для рентгенолаборанта,
врача и инженера, который обрабатывает пакет исследований. Как установить
сервис — `docs/deployment.md`.

Сервис — помощник, а не врач: он отмечает типовые нарушения укладки и
разметки, но не заменяет просмотр исследования специалистом. Что именно он не
проверяет — раздел «Чего сервис не видит» в конце.

## 1. Веб-интерфейс

Откройте в браузере адрес, который дал администратор (на своём компьютере —
`http://localhost:8000/` после `./run.sh --serve`).

1. **Загрузка.** Перетащите в рамку zip-архив с исследованиями или
   DICOM-файлы одного исследования (можно выбрать кнопкой). Архив может
   содержать сколько угодно исследований в любой структуре каталогов:
   исследование — каталог верхнего уровня. Флажок «Строить overlay-серию»
   включён по умолчанию; без него обработка быстрее, но картинок не будет.
2. **Обработка.** Нажмите «Обработать». Сначала идёт загрузка (полоса), потом
   обработка — около 0.3 с на исследование.
3. **Сводка** над таблицей: сколько исследований и файлов, сколько
   исследований и изображений с нарушениями, сколько файлов не прочитано,
   среднее время на исследование. Кнопки с типами нарушений фильтруют таблицу.
4. **Таблица** сгруппирована по исследованиям. В строке исследования — его
   вердикт: «качественное», «есть нарушения» или «есть ошибки» (не все файлы
   прочитаны). Фильтры «С нарушениями / Норма / Ошибки чтения» и поиск по
   пути, исследованию, нарушению.
5. **Просмотр.** Щелчок по строке (или стрелки ↑↓ на клавиатуре) открывает
   справа overlay снимка — изображение с измерениями, по которым принято
   решение, — и расшифровку нарушений. Кнопка «DICOM overlay» скачивает этот
   снимок как DICOM-объект для PACS.
6. **Скачивание:** «Таблица .xlsx», «Таблица .csv», «Overlay-серия .zip».

Загруженные файлы удаляются сразу после обработки. Сервис хранит результаты
пяти последних обработок; в контейнере — до его перезапуска.

## 2. Что означает результат

### Колонки таблицы

| колонка | что в ней |
|---|---|
| `path_to_study` | путь к файлу внутри архива или каталога |
| `study_uid`, `image_uid` | StudyInstanceUID и SOPInstanceUID из тегов файла |
| `anatomical_region` | область: поясничный отдел позвоночника, проксимальный отдел левого или правого бедра; «Не определена», если область распознать не удалось |
| `quality_class` | 0 — нарушений не найдено, 1 — есть нарушение; пусто, если файл не обработан |
| `violation_type` | перечень нарушений через `;` (коды ниже); у необработанного файла — причина ошибки |
| `processing_status` | `Success` или `Failure` |
| `time_of_processing` | время обработки файла, с |
| `quality_score` | балл нарушения от 0 до 1: чем выше, тем вероятнее нарушение; больше 0.5 — ровно тогда, когда `quality_class` = 1; удобен, чтобы разбирать спорные снимки по убыванию балла |
| `study` | исследование — имя каталога верхнего уровня |
| `projection` | проекция: из тега ViewPosition, а без него — прямая (AP), как положено по протоколу |

Строка — на каждый файл, в том числе на точные копии одного снимка.

### Типы нарушений

| код | область | что значит | как видно на overlay |
|---|---|---|---|
| `SPINE_POSITIONING` | позвоночник | в кадр не попали верхние края подвздошных костей | красная горизонтальная линия — граница нижней трети кадра, где искали гребни |
| `SPINE_AXIS_TILT` | позвоночник | ось позвоночника отклонена от вертикали больше допустимого (порог 4.5°) | красная линия — ось, серая — вертикаль; в шапке угол |
| `SPINE_ARTIFACT` | позвоночник | посторонние предметы, выраженные артефакты или наложения (чаще всего — рёбра) | цветная карта отклика и красный кружок в самом сильном месте |
| `FEMUR_POSITIONING_ROTATION` | бедро | конечность пере- или недоротирована: малый вертел не виден совсем или выступает слишком сильно | голубая линия — медиальный край бедра, жёлтые штрихи — окно малого вертела, кружок — место измерения выступа |
| `FEMUR_ROI_COVERAGE` | бедро | поле сканирования слишком короткое: не хватает отступов 3 см сверху и снизу от области интереса | красная рамка — поле сканирования, в шапке его длина |

### Как читать overlay

* Зелёный контур — найденная кость.
* **Красное** — сработавшее правило, **жёлтое и голубое** — измерение,
  которое нарушения не дало, серое — справка.
* В шапке — область, итог и числа против порогов, например
  `axis tilt 6.2 deg > limit` или `scan length 124 mm - too short for ROI
  margins`. Подписи латиницей: так их можно вшить в пиксели без шрифтов.
* Строка `lateral margin … mm (TZ 20 mm, info only)` у бедра — справка:
  боковой отступ против 2 см из ТЗ. На решение она не влияет — эксперт
  организатора этот критерий на данных не применяет ([«Ограничения»,
  п. 6](limitations.md#6-боковое-правило-20-мм-из-тз-на-этих-данных-опровергается)).

## 3. Командная строка и API

Пакетная обработка каталога или архива в контейнере, без сети:

```bash
./run.sh <каталог или zip с исследованиями> <каталог для результатов>
```

В каталоге результатов: `result.xlsx`, `overlays.zip` (на каждый файл PNG и
DICOM Secondary Capture, на каждое исследование — текстовый отчёт DICOM SR
`DXA_QC_report.sr.dcm`) и `diagnostics.csv` — те же строки плюс все
измерения против порогов, для разбора спорных случаев. HTTP API для
интеграции — `POST /batch`, описание — в [api.md](api.md) и на странице `/docs`
сервиса.

## 4. Если что-то пошло не так

| что видно | почему | что делать |
|---|---|---|
| `Failure`: «файл не является DICOM» | в архиве посторонний файл (например, `разметка.xlsx`) | ничего: строка оставлена, чтобы файл не пропал молча |
| `Failure`: «цветное изображение … не поддерживается» | снимок экрана или отчёт вместо денситометрии | проверить, тот ли файл выгружен |
| `Failure`: «PixelData обрезан» | файл повреждён при копировании | выгрузить заново |
| `Failure`: «не удалось определить анатомическую область» | пустой, однотонный или не денситометрический кадр | проверить снимок глазами |
| «Не определена» у области, пустой `quality_class` | то же | то же |
| предупреждение о масштабе в журнале | в тегах нет размера пикселя, миллиметры взяты из Exposed Area и паспорта аппарата | ничего; на другом аппарате длины могут быть смещены ([«Ограничения», п. 9](limitations.md#9-масштаб-изображения-восстанавливается-косвенно)) |
| предупреждение «больше 3 уникальных кадров» в журнале | скорее всего, несколько исследований попали в один каталог (ТЗ 2.4: не больше трёх снимков в исследовании) | проверить, что исследования лежат в отдельных каталогах; обрабатываются все файлы |
| «задание не найдено» по старой ссылке | хранятся пять последних обработок | обработать заново |

Ни одна ошибка в отдельном файле не останавливает обработку остальных.

## 5. Чего сервис не видит

* Половину тела Th12 в верхней части кадра позвоночника — только гребни
  подвздошных костей внизу.
* Отдельно — видимость большого вертела, шейки и седалищной кости; ротацию
  бедра — да.
* Точное положение малого вертела. Кружок на overlay бедра — место, где
  правило мерило выступ. На 58 снимках, где вертел отметил врач, кружок
  отстоит от его точки обычно (медиана) на 9 мм, в пределах 5 мм — на
  каждом четвёртом. Если кружок
  явно не на вертеле, вердикт по ротации стоит перепроверить глазами.
  Более точный локализатор проверялся, но ротацию он определял хуже и в
  сервис не включён.
* Сколиоз: искривлённый позвоночник может получить `SPINE_AXIS_TILT`, хотя
  эксперт считает это анатомией, а не ошибкой укладки. При известном
  сколиозе вердикт по оси стоит перепроверить.
* Снимок другой области (предплечье, всё тело) будет отнесён к одной из трёх
  областей и проверен её правилами.

Подробно и с цифрами — [«Ограничения»](limitations.md).
