# Демонстрационный сценарий

[← README](../README.md) · [Карта документации](README.md)

Сценарий показа сервиса (ТЗ 4, пункт 9; ТЗ 7.2 — «презентация и
демонстрационный сценарий»). Время — 6–8 минут. Слайды —
`presentation/DXA_QC_presentation.pptx`, слайды 18–19 («Кейсы», «Демонстрация»).

Все кейсы — из обучающего набора `Data/НД_для_обучения.zip`: показываем,
как сервис объясняет решение, а не качество на новых данных (его считает
организатор на закрытом наборе).

## 0. Подготовка (до показа)

```bash
./build.sh
docker run --rm --network none dxa-qc:latest health
./run.sh --serve
```

* `health` — `"status": "ok"`, обе модели `"loaded": true`.
* Открыть `http://localhost:8000/` и `http://localhost:8000/docs` в двух
  вкладках.
* Заранее прогнать пакет, чтобы не ждать на показе:
  `./run.sh Data/НД_для_обучения.zip /tmp/demo_out` — в каталоге
  `result.xlsx`, `overlays.zip`, `diagnostics.csv`.
* Запасной вариант без Docker — `PYTHONPATH=src python -m dxa_qc.service`
  (нужно окружение из `requirements.txt`); без сети и компьютера — слайды
  18–19 и `result.xlsx` из `/tmp/demo_out`.

## 1. Пакет исследований за секунды (1–2 мин)

1. В веб-интерфейсе перетащить `Data/НД_для_обучения.zip` (весь набор
   организатора как есть, 100 исследований, имена в cp866), оставить галочку
   overlay-серии, нажать «Обработать».
2. Показать сводку: исследования, файлы, сколько исследований и снимков с
   нарушениями, 0 ошибок чтения, время на исследование.
3. Фильтр «С нарушениями», затем фильтр по типу (например, «Ротация
   бедра») — таблица по исследованиям с общим вердиктом.
4. Скачать `result.xlsx`: восемь колонок ТЗ 2.5 в нужном порядке, после них
   `quality_score`, `study` и `projection`. Балл `quality_score` — для ROC-AUC
   (ТЗ 8.4): больше 0.5 ровно у снимков с нарушением, а внутри класса
   показывает, насколько измерение за порогом; отсортировать по нему — и
   спорные снимки окажутся рядом с 0.5. Строка `разметка.xlsx` — `Failure` с причиной:
   не-DICOM файл не пропускается молча.

## 2. Решение видно на снимке (3 мин)

В поле поиска вставить идентификатор исследования, кликнуть по строке
снимка — справа откроется overlay.

| кейс | исследование | снимок | что показать |
|---|---|---|---|
| норма, позвоночник | `2.25.108537195937431169718850276671337677972` | CR000000 | жёлтая ось 1.6°, гребни подвздошных костей в кадре — «OK» |
| наклон оси | `2.25.37515662379281069436632838996073181551` | CR000000 | красная ось 6.7° при пороге 4.5°; у эксперта — «хороший пример отклонения оси» |
| укладка | `2.25.125521310320333648427417313254965624364` | CR000000 | красная линия — нижняя треть кадра: гребней нет |
| артефакт | `2.25.11175860580562939441493697221497597640` | CR000001 | карта отклика top-hat и красный кружок в самом сильном месте |
| два нарушения | `2.25.126293418391331346694592071563510265596` | CR000002 | левое бедро: поле 125 мм (порог 133) и выступ вертела вне нормы — оба кода через «;» |
| честная ошибка | `2.25.112621744005021908434051268014787122937` | CR000000 | сколиоз: сервис видит наклон 9.3°, эксперт — норма; это ограничение п. 3 README |

Для одного кейса нажать «↓ DICOM overlay (Secondary Capture)» — объект в том же
исследовании, отдельная серия `DXA QC overlay`: открывается в любом
DICOM-просмотрщике и загружается в PACS рядом с оригиналом. В
`overlays.zip` у каждого исследования лежит и текстовый отчёт DICOM SR
`DXA_QC_report.sr.dcm` (ТЗ 2.6): заключение, нарушения словами ТЗ,
измерения против порогов и ссылки на снимки — открыть в просмотрщике с
поддержкой SR (например, Weasis или OHIF).

Что проговорить: красное — сработавшее правило, жёлтое и голубое —
измерение без нарушения, в шапке — числа против порогов. Решение не «чёрный
ящик»: врач видит, что именно измерено.

## 3. API для пакетной обработки (1 мин)

Во вкладке `/docs` показать три метода, у `/batch` — описание ответа
(xlsx, csv или zip). Из терминала:

```bash
curl -F "file=@Data/Для теста.zip" "http://localhost:8000/batch?format=csv"
curl -F "file=@Data/НД_для_обучения.zip" "http://localhost:8000/batch?overlays=true" -o result.zip
```

Первый запрос возвращает таблицу сразу в терминал, второй — zip с
`result.xlsx` и `overlays.zip`. Это тот же конвейер, что у командной строки
и веб-интерфейса: таблицы совпадают построчно.

## 4. Устойчивость и работа без сети (1 мин)

1. Переименовать любой текстовый файл в `junk.dcm` и загрузить в
   веб-интерфейс вместе с файлами одного исследования (например, из
   `Data/Для теста/`): у него строка `Failure` с причиной, остальные файлы
   обработаны.
2. Показать команду пакетного прогона в `run.sh`: контейнер запускается с
   `--network none`, вход монтируется только на чтение.
3. Цифры для ответа на вопросы: весь набор — 7 с без overlay и 30 с с
   overlay-серией; стресс-тест (`reports/stress/summary.json`) — 77
   испорченных и нестандартных файлов, 0 вылетов.

## Частые вопросы на показе

* **Почему не нейросеть?** Слайд 11: на 6–36 позитивах обучаемые модели
  правилам не выиграли на тех же фолдах; ResNet18 на области вертела — в
  пределах шума, но требует torch в образе.
* **Насколько точна точка вертела?** Медиана 9.0 мм до точки врача (58
  снимков). Точный локализатор (2.5 мм) проверен, но правило ротации в его
  точке хуже — не включён по заранее зафиксированному критерию.
* **Что будет на другом аппарате?** Масштаб берётся из тегов, если они есть;
  без них — паспорт GE Lunar. Пороги пересчитываются по `docs/training.md`.
