# Процедура обучения и дообучения

[← README](../README.md) · [Карта документации](README.md)

В решении почти нечего «обучать» в привычном смысле: три правила из пяти —
геометрия маски кости с порогом, детектор артефактов — логистический порог
на одном физическом признаке, правило ротации — две границы на одном
признаке. Поэтому «обучение» здесь — это выбор порогов и признаков на
размеченном наборе с честной проверкой на отложенных фолдах. Здесь описано,
как воспроизвести это с нуля и как пересчитать на новых размеченных данных.

## 1. Что подбирается и где хранится

| компонент | что подбирается | где хранится | скрипт |
|---|---|---|---|
| роутер области | пороги латеральности и симметрии кадра | `routing.py`: `LAT_SPLIT = 41.5`, `SYM_SPINE = 0.42` | `02`, `05` |
| маска кости | ничего (трёхклассовый Otsu и ограниченный гистерезис) | `segmentation.py` | `04` — проверка глазами |
| укладка позвоночника | порог плотности сбоку в нижней трети кадра | `spine.py`: `COVERAGE_MIN = 0.04` | `07` |
| наклон оси | порог угла главной оси | `spine.py`: `AXIS_TILT_DEG = 4.5` | `06`, `07` |
| артефакты | логистическая регрессия на признаке top-hat | `models/artifact_tophat_v1.npz` (1.6 КБ) | `08` |
| охват области интереса | порог длины поля сканирования | `femur.py`: `FIELD_MIN_MM = 133.0` | `09` |
| ротация бедра | признак из четырёх и две границы нормы | `models/rotation_profile_v1.json` (1.2 КБ) | `14`, `17` |
| балл `quality_score` | крутизна перевода маржи каждого правила в вероятность (без свободного члена) | `models/quality_score_v1.json` | `26` |
| локализатор малого вертела v2 (отклонён) | средний шаблон патчей 18×18 мм по 58 точкам врача; затем один из трёх признаков и две границы | не развёрнут; OOF-шаблоны и решения в `reports/rotation_localizer/` | `20`, `21`, `22` (22 не пишет модель при no-go) |

Файлы моделей несут версию признаков (`feature_version`): если код признака
изменился, а модель не пересчитана, модуль её не примет, а сборка образа
остановится на проверке загрузки моделей.

Проверенные и отклонённые альтернативы (обучаемая голова на геометрии и
изображении, CNN) — `scripts/16_multilabel_head.py`,
`reports/day8_multilabel.md`: по агрегату они правилам не выигрывают.

## 2. Окружение

Python 3.12, зависимости разработки — `requirements.txt` (версии закреплены):

```bash
python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
pip install -e . --no-deps
pytest -q
```

Для обучения GPU не нужен; весь цикл ниже — минуты на CPU.

## 3. Данные и разбиение

* Снимки — `Data/НД_для_обучения/Исследования/<исследование>/…/*.dcm`.
* Разметка — `Data/НД_для_обучения/разметка.xlsx` в формате организатора:
  первый лист, две строки шапки (область и критерий), затем строка на
  исследование: номер, имя каталога исследования, три критерия
  позвоночника, по два критерия каждого бедра, итоги. Соответствие
  столбцов типам нарушений — `taxonomy.yaml`.
* Разметка дана на «исследование × область», а таблица — на изображение.
  `02_build_dataset.py` спускает метки на изображения: снимки
  дедуплицируются по пикселям, каждому уникальному снимку назначается
  область по геометрии с учётом состава исследования из разметки.
* Разбиение `reports/split.csv` — пять фолдов, **единица — исследование**:
  позвоночник и оба бедра одного пациента всегда в одном фолде, утечки
  между обучением и проверкой нет.
* Точки на 80 снимках бедра (`annotations/femur_points_human.csv`) ставил
  врач. Они используются только для проверки и разбора ошибок ротации, на
  инференсе — никогда.

## 4. Полный цикл с нуля

```bash
R="Data/НД_для_обучения/Исследования"

# данные
python scripts/01_inventory.py --root "$R" --out reports/inventory_train.csv
python scripts/02_build_dataset.py --inventory reports/inventory_train.csv \
    --markup "Data/НД_для_обучения/разметка.xlsx" --root "$R" --out reports/dataset_images.csv
python scripts/03_make_split.py --dataset reports/dataset_images.csv --out reports/split.csv --seed 42
python scripts/04_segment_qc.py --dataset reports/dataset_images.csv --root "$R" \
    --out-csv reports/segmentation_qc.csv --out-dir reports/qc_sheets
python scripts/05_router_check.py --dataset reports/dataset_images.csv

# сквозной прогон: его диагностику сверяют скрипты правил
python -m dxa_qc.batch --input "$R" --output reports/result_train.xlsx \
    --diagnostics reports/batch_diagnostics_train.csv

# правила позвоночника и артефакты
python scripts/06_spine_axis.py --dataset reports/dataset_images.csv --root "$R" --out reports/spine_axis.csv
python scripts/07_spine_rules.py --dataset reports/dataset_images.csv --root "$R" \
    --out reports/spine_rules.csv --diagnostics reports/batch_diagnostics_train.csv
python scripts/08_train_artifact.py --root "$R"             # -> models/artifact_tophat_v1.npz

# бедро
python scripts/09_femur_rules.py --root "$R" --out reports/femur_rules.csv \
    --diagnostics reports/batch_diagnostics_train.csv
python scripts/14_rotation_human_profile.py                 # вложенная проверка ротации
python scripts/17_fit_rotation_rule.py                      # -> models/rotation_profile_v1.json
python scripts/20_trochanter_localizer.py                   # локализатор v2: OOF по точкам врача
python scripts/21_rotation_v2_nested.py                     # двойной кросс-фиттинг и вердикт
python scripts/22_fit_rotation_v2.py                        # при no-go models/ не меняется

# итоговые метрики, балл и сверка конвейера
python scripts/15_checkpoint_metrics.py
python scripts/26_quality_score.py                          # -> models/quality_score_v1.json, ROC-AUC вложенно
python scripts/verify_day6_pipeline.py
pytest -q
```

После правок в коде, которые не меняют решений, отчёты, зависящие от
сквозного прогона, пересчитывает одна команда —
`./scripts/refresh_reports.sh`: прогон обучающего набора сверяется со
старым эталоном и только при полном совпадении решений становится новым,
затем пересчитываются метрики (15), сверка конвейера и стресс-тест (18).

Что проверять по выходу:

* `04` — контактные листы `reports/qc_sheets/`: маска кости легла на кость;
* `05` — 0 расхождений области с разметкой;
* `08` — `reports/artifact_cv.json`: F1 и ROC-AUC на out-of-fold, порог берётся
  из обучающих фолдов, а не из OOF;
* `14` — `reports/rotation_human_profile/summary.json`: F1 вложенной
  проверки (признак и границы выбираются внутри обучающих фолдов);
* `20`, `21` — `reports/rotation_localizer/`: ошибка локализации вертела до
  точки врача (`localization.csv`) и вердикт v2 первой строкой
  `reports/day12_rotation_localizer.md`; критерий включения зафиксирован
  там же до проверки. Сравнение с ResNet18 берётся из ветки
  `codex/day21-rotation-transfer`, без неё — из закоммиченного снимка;
* `15` — `reports/checkpoint_day9/`: метрики по областям, типам и в целом с
  ДИ 95% (бутстреп по исследованиям), плюс «честные» пороги геометрических
  правил, подобранные на четырёх фолдах и применённые к пятому;
* `verify_day6_pipeline.py` — `"passed": true`: решения конвейера совпадают
  с таблицами правил, повтор и второй ридер дают то же.

## 5. Дообучение на новых размеченных данных

1. Положить новые исследования в `Исследования/`, дописать их строки в
   `разметка.xlsx` в том же формате.
2. `01` и `02` — заново. `03` пересобирает разбиение целиком: все прежние
   цифры сдвинутся, это нормально, но сравнивать «до» и «после» можно только
   на одном разбиении.
3. **Артефакты:** `08` переобучает порог и пишет новый
   `models/artifact_tophat_v1.npz`.
4. **Ротация:** `14` (вложенная проверка на новых данных), затем `17`
   (заморозка признака и границ на всех данных) → новый
   `models/rotation_profile_v1.json`.
5. **Геометрические пороги** — константы в коде. `15` печатает пороги,
   выбранные честно на каждом фолде (`nested_thresholds.csv`). Менять
   константу стоит, только если честная оценка с новым порогом выше и
   порог устойчив между фолдами; выбирать порог по всем данным и тут же
   мерить на них нельзя — это оптимистичная цифра.
6. **Балл:** `26` заново подгоняет крутизну правил → новый
   `models/quality_score_v1.json` и вложенный ROC-AUC в
   `reports/quality_score/summary.json`.
7. `15`, `verify_day6_pipeline.py`, `pytest -q` — всё зелёное.
8. `./build.sh` — новые файлы моделей попадут в образ, `health` покажет их
   sha256.

## 6. Правила честной проверки

* Любой порог или выбор признака — только на обучающих фолдах, оценка — на
  отложенном; для процедур с выбором (ротация) — вложенная проверка.
* Группировка по исследованию и в разбиении, и в бутстрепе ДИ.
* Цифры «на обучении» (пороги по всем данным) и «честные» в отчётах
  всегда подписаны отдельно; в README и в презентации главная — честная.
* Точки врача не передаются в признаки конвейера: ими только меряется
  ошибка локализации.
