## 1. Сквозной прогон работает, твои модели встают в одну функцию

```
python -m dxa_qc.batch --input <каталог с исследованиями> --output result.xlsx
```

499 строк на обучающем наборе, 0 ошибок, 1.5 с на 100 исследований. Обход
каталога, чтение DICOM, определение области, обработка ошибок, формат таблицы
ТЗ 2.5 — всё готово. Заглушка одна:

```python
# src/dxa_qc/batch.py
def predict_stub(region: str, img: DicomImage) -> tuple[int, str]:
    return 0, ""
```

**Контракт:** возвращает `quality_class` (0 или 1) и строку `violation_type` —
идентификаторы нарушений из `taxonomy.yaml` через `;`, пустая строка если
нарушений нет. Твои классификаторы (артефакты, ротация) подключаются сюда же.
Договоримся о сигнатуре, когда у тебя будут веса — скорее всего понадобится
передавать ещё маску кости, чтобы не считать её дважды.

## 2. Роутер области уже сделан геометрией — это меняет твой приоритет

`src/dxa_qc/routing.py` определяет область без разметки и без обучения:
**0 расхождений с просмотренным глазами эталоном на всех 252 изображениях**
(99 позвоночников, 79 левых бёдер, 74 правых). Проверка —
`python scripts/05_router_check.py --dataset reports/dataset_images.csv`.

Правило: позвоночник, если `|lat_score| < 41.5` (кадр центрирован) **или**
`sym > 0.42` (кадр зеркально симметричен); дальше сторона бедра по знаку
`lat_score`. Каждое решение помечается флагом уверенности.

**Что это значит.** Классификатор области на 3 класса из плана на 16-е больше
не на критическом пути: у нас уже 100% на обучающем наборе. Его стоит сделать
не вместо, а рядом — как страховку на закрытых данных, где геометрия может
поплыть (например, другой аппарат с другой шириной кадра). Если у тебя он ещё
не готов, приоритет ниже, чем у разметки бедра и классификатора артефактов.

**Аномалия, из-за которой правило переписывалось.** Цифры дня 2
(«у позвоночника |lat| не больше 27.5, у бедра не меньше 47.8») неверны: они
были сняты до исправления трёх перепутанных областей. На самом деле классы
**соприкасаются** — позвоночник доходит до 56.7, бедро начинается с 45.3.
Абсолютный порог на этом ошибался на 7 позвоночниках из 99. Если где-то в
своём коде опирался на эти числа — перепроверь.

## 3. Главная аномалия дня: сколиоз ломает правило наклона оси

Правило ТЗ 2.3.1 упирается в AUC 0.88, и причина не в геометрии.

* Маска позвоночника — узкая вертикальная полоса (ширина bbox 101 пиксель при
  кадре 300, одна компонента). Рёбер и таза в ней нет, выделять столб нечего.
* Пять разных способов оценить угол дают 0.607…0.883 — разброс лучших трёх в
  пределах шума на 10 позитивах.
* **Из 20 позвоночников с находкой вне перечня ТЗ 2.3 нарушением оси помечен
  ровно один.** Эксперт систематически считает отклонение оси при сколиозе
  анатомией, а не ошибкой укладки. Из 10 ложных срабатываний при 4.5° шесть —
  такие случаи.

Список: `reports/out_of_scope_spine.csv` (20 исследований, из них 14 со
сколиозом, с углами и признаками кривизны). Признаки по всем 99
позвоночникам — `reports/spine_axis.csv`.

**Что из этого твоё.**

* **Метрический модуль:** метрики считаем по полной выборке — это честная
  метрика решения. Дополнительно нужен тот же расчёт по подвыборке **без**
  исследований из `out_of_scope_spine.csv` — как диагностика источника ошибок
  для разбора 26-го и слайда по критерию 8.1. Выкидывать их из основной
  метрики нельзя: на инференсе не выкинешь.
* **Классификатор артефактов:** проверь, не пересекаются ли твои 17 позитивов
  с этим списком. Эндопротез — это металл, но эксперт разметил его не как
  артефакт, а область с ним не разметил вообще (2 исследования, `labeled=False`
  в `dataset_images.csv`).
* **Разметка бедра:** два бедра с эндопротезом размечать не надо, в обучение
  они не идут.

## 4. Таксономия закрыта

Флаг `OUT_OF_SCOPE_FINDING` (сколиоз 14, эндопротез 2, перелом 1,
люмбализация 1) **не влияет на `quality_class`**, но попадает в
`violation_type` отдельной пометкой. Это не осторожность: если дать ему
влиять на `quality_class`, получим 14 ложных срабатываний на сколиозе против
одного совпадения с экспертом. Подробности — в комментарии в `taxonomy.yaml`.

## 5. Контрольная точка 18-го: решение принято, переоткрывать не нужно

Бутстреп на 10 позитивах: AUC 0.878, **ДИ 95% [0.794, 0.946]**. Порог
контрольной точки 0.9 лежит внутри интервала, по фолдам разброс 0.688–1.0.
Критерий «если AUC < 0.9, переходим на резервный CNN» на таких данных
неразрешим, а сам резерв приближает ту же геометрию и потолок не поднимет.

Решили: правило принимаем с порогом **4.5°** по главной оси маски
(чувствительность 0.70, специфичность 0.88, F1 0.50). Признак кривизны
(`res_rms`, AUC 0.788 по сколиозу) идёт вторым входом мультилейбл-головы
22–23 сентября. Конфликт правила с анатомией пишем в «Ограничения» и выносим
на слайд по критерию 8.5 как разобранное ограничение.

## 6. Мелочи, которые заметны в выходной таблице

* `anatomical_region` заполняется по-русски, словами ТЗ 2.3. Ключ
  `--region-lang code` даёт короткие коды.
* Добавлена **девятая колонка `study`** — имя каталога, тот ключ, по которому
  сделана `разметка.xlsx`. Стоит после восьми колонок ТЗ, позиционный разбор
  первых восьми не меняется.
* Строка — на каждый **файл**, включая точные дубли (их половина набора).
  Дедупликация только внутри конвейера.
* У строки с `processing_status=Failure` колонка `quality_class` **пустая**,
  не 0: ноль означал бы «снимок качественный». Текст ошибки — в
  `violation_type`.
