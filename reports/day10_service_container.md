Сделано за один заход вечером 22-го: пункты плана на 24-е (API, образ,
скрипты сборки и запуска) и на 25-е (стресс-тест, замер ресурсов). Тесты:

## 1. Вход из zip и уровень каталога (`src/dxa_qc/archive.py`)

ТЗ 2.7 требует пакетную обработку «из архива». Проверка на архивах
организатора нашла две вещи, которые сломали бы прогон молча:

* **имена в cp866 без флага UTF-8** — стандартный `zipfile` читает
  «Исследования» как «êßß½Ññ«óá¡¿∩». Теперь имена перекодируются (UTF-8,
  затем cp866);
* **обёртка каталогов** — в `НД_для_обучения.zip` исследования лежат в
  `Исследования/`, рядом `разметка.xlsx`. Исследование — первый компонент
  пути, и все 499 файлов стали бы одним исследованием, а роутер допускает
  один позвоночник на исследование. Теперь обёртки снимаются: пока на
  уровне один подкаталог, нет DICOM и под ним больше 50 файлов (самое
  большое исследование — 29). То же работает для каталога
  `НД_для_обучения/`. Если исследование всё равно содержит больше трёх
  уникальных кадров (ТЗ 2.4), печатается предупреждение.

Проверено: `НД_для_обучения.zip`, `НД_для_обучения/` и `Исследования/`
дают одинаковые строки по всем 499 снимкам; архив и каталог добавляют
строку `Failure` на `разметка.xlsx`, как на любой не-DICOM файл.
`Для теста.zip` — одно исследование из трёх кадров, обёртка не снимается.

Распаковка безопасна: `..`, абсолютные пути и символические ссылки
отвергаются, размер и число файлов ограничены (переменные
`DXA_QC_MAX_UNZIP_BYTES`, `DXA_QC_MAX_UNZIP_FILES`).

## 2. HTTP API (`src/dxa_qc/service.py`)

| метод | путь | что делает |
|---|---|---|
| GET | `/health` | статус, версия, загружены ли модели, их sha256 |
| POST | `/batch` | zip → таблица (`format=xlsx\|csv`); с `overlays=true` — zip с таблицей и `overlays.zip` |
| POST | `/predict` | файлы одного исследования → JSON со строками и итоговым классом |

Тонкая оболочка над `batch.run`: таблица API совпадает с CLI построчно
(тест). Загрузка пишется на диск потоком, прогоны сериализованы
блокировкой, временные файлы удаляются после ответа. Логика вынесена в
функции без FastAPI и тестируется в облаке; HTTP-тесты
(`fastapi.testclient`) — на Mac.

## 3. Образ (`Dockerfile`, `build.sh`, `run.sh`, `docker/`)

* Основа `python:3.12.7-slim-bookworm` — тот же Python 3.12, на котором
  прошла сверка на пинах. После первой сборки `build.sh` печатает digest
  основы — его надо дописать в `FROM`.
* `docker/requirements-runtime.txt` — только инференс и API, 20 пакетов,
  все версии закреплены, включая транзитивные (взяты из проверенного
  `.venv`, замкнутость проверена по METADATA). Установка
  `--no-deps --only-binary=:all:` + `pip check`: нет колеса — сборка падает
  сразу.
* torch, torchvision, timm, albumentations, pandas, scikit-*, scipy в
  образ не входят. Проверено, что конвейер их не импортирует (при сборке
  — assert). Образ меньше на ~1.5 ГБ.
* Дымовая проверка при сборке: модули, обе модели, приложение FastAPI.
  `build.sh` после сборки запускает `health` с `--network none`.
* Процесс — не root; `run.sh` запускает с `--user $(id -u):$(id -g)`,
  чтобы результаты принадлежали пользователю.
* `./run.sh <вход> <выход>` — пакетный прогон с `--network none`, вход
  только на чтение, на выходе `result.xlsx`, `overlays.zip`,
  `diagnostics.csv`. `./run.sh --serve` — API на `127.0.0.1:8000`.
* Для машины организатора (x86_64): `PLATFORM=linux/amd64 ./build.sh --save`.

**В облаке Docker-демона и доступа к реестру нет, поэтому образ здесь не
собирался.** Всё, что можно проверить без сборки, проверено: синтаксис
скриптов, состав зависимостей, отсутствие тяжёлых импортов, работа
точки входа.

## 4. Стресс-тест (`scripts/18_stress_test.py`)

77 файлов: пустой, текст с расширением `.dcm`, случайные байты, xlsx,
обрезанные пиксели, 1×1, однотонный, RGB, JPEG без декодера, без
преамбулы, кадр 2048×2048, 29 копий одного кадра, кириллица и пробелы в
путях, пустое исследование, пустой архив; шесть реальных кадров (по
одному на каждый тип решения и норма), перепакованные в MONOCHROME1,
16 бит, Explicit VR Big Endian, без Exposed Area и с PixelSpacing.

| проверка | итог |

| исключения наружу | 0 |
| строка на каждый файл | 77 из 77, каталогом и архивом одинаково |
| Failure с причиной и пустым классом | 9 из 9 |

## 6. Первый прогон на Mac (23 сентября) и исправления

Прогон pytest на пинах нашёл две ошибки, которых облако без FastAPI и
pydicom не видело. Обе исправлены и воспроизведены в облаке: чистые
pydicom 3.0.1, FastAPI 0.115.4 и Starlette 0.41.3 скопированы из `.venv`,
после этого **277 тестов, 0 упавших, 0 пропущенных**.

* **FastAPI не создавал приложение.** В `service.py` стоял
  `from __future__ import annotations`, аннотации стали строками, а
  `UploadFile` импортируется внутри `create_app` — FastAPI искал его в
  глобалах модуля и падал. Импорт убран, причина записана в docstring.
  Все пять HTTP-тестов проходят.
* **Текст ошибки не был воспроизводим.** На битом JPEG pydicom пишет
  ошибку pillow с адресом объекта в памяти
  (`<_io.BytesIO object at 0x7f95…>`), и этот текст уходит в
  `violation_type`. Каталог и архив — и любые два прогона — давали разные
  таблицы, то есть нарушалась воспроизводимость ТЗ 2.7. Теперь текст
  ошибки чистится (`dicom_io.stable_error`): адреса убираются, полный
  путь заменяется именем файла, переводы строк — пробелами. На 499 файлах
  обучения таблица не изменилась (там нет Failure).

## 6а. Образ собран и проверен на Mac (Docker Desktop 4.92, arm64)

Первая сборка прошла, но сервис в контейнере не нашёл `dxa_qc`: файлы на
Mac имеют права 600, `COPY` переносит их как есть, а сервис работает от
пользователя `dxa`. Дымовая проверка шла от root и этого не видела.
Исправлено: `chmod -R a+rX /app`, проверка перенесена после `USER dxa`.
Базовый образ закреплён digest
`python:3.12.7-slim-bookworm@sha256:60d9996b…b50d` (мультиплатформенный индекс).

Итог:

* образ `dxa-qc:0.2.0`, arm64, 332 МБ; `health` без сети — обе модели загружены;
* `./run.sh Data/НД_для_обучения.zip /tmp/out_docker` — 500 строк, 499
  Success, 1 Failure (`разметка.xlsx`), 499 картинок overlay без ошибок,
  18.7 с на M2; распределение нарушений (ротация 97, охват 15,
  артефакты 37, наклон 30, укладка 5) совпадает с прогоном без Docker.
* образ под машину проверки: `PLATFORM=linux/amd64 ./build.sh --save` →
  amd64, 389 МБ, файл `dxa-qc_0.2.0.tar.gz` 131 МБ (в `.gitignore`);
  прогон того же архива на amd64 (эмуляция, 25.6 с) дал **таблицу,
  совпадающую с arm64 во всех 500 строках** — решения не зависят от
  архитектуры, пороги не сидят на ошибках округления.

## 7. Что проверить на Mac

В zsh комментарии в интерактивной строке не работают — `#` уходит
аргументом в скрипт. Команды без комментариев:

```bash
.venv/bin/python -m pytest tests -q
./build.sh
./run.sh Data/НД_для_обучения.zip /tmp/out_docker
./run.sh --serve
```
