## 1. Заглушки больше нет, функция называется `predict` и возвращает три значения

Было:

```python
def predict_stub(region: str, img: DicomImage) -> tuple[int, str]:
    return 0, ""
```

Стало:

```python
def predict(region: str, img: DicomImage) -> tuple[int, str, dict]:
    # -> quality_class, violation_type, диагностика
```

Третье значение — словарь служебных колонок. Он попадает **только** в
диагностический csv (`--diagnostics`), в таблицу ТЗ 2.5 не идёт. Клади туда
всё, что понадобится при разборе ошибок 26-го: вероятности классов, метку
фолда, что угодно. Ключи у разных строк могут отличаться, таблица соберёт
объединение.

`violation_type` — прежний контракт: идентификаторы из `taxonomy.yaml`
через `;`, пустая строка при отсутствии нарушений. `quality_class` — 1,
если перечень непуст.

**Важно про производительность.** Предсказание теперь считается один раз на
уникальный кадр исследования, копии наследуют результат (половина файлов
набора — точные копии). Твой классификатор попадёт в ту же схему
автоматически, отдельно кэшировать ничего не надо. Маска кости считается
внутри `predict` один раз и передаётся правилам — когда будешь встраивать
свою модель, бери её оттуда же, а не сегментируй заново.

## 2. Позвоночник закрыт целиком, включая артефакты

| правило | F1 |
|---|---|
| наклон оси | 0.50 |
| укладка | 0.80 |
| артефакты (out-of-fold) | 0.71 |

**Детектор артефактов сделан за тебя** — отдельный отчёт
`reports/day4_artifact.md`, читать его целиком. Коротко: CNN из плана не
обучается на 17 позитивах, и это проверено прямым сравнением на тех же
фолдах (HOG 144 признака — ROC-AUC 0.58, F1 0.01). Работает один физический
признак: 99.9-й перцентиль отклика top-hat вне маски позвоночника. Веса —
1650 байт, ни torch, ни sklearn на инференсе.

Чувствительность агрегата `quality_class` по позвоночнику выросла с 0.44 до
**0.75**, F1 с 0.52 до 0.71.

Метрический модуль (`src/dxa_qc/metrics.py`) — тоже сделан: полный набор
ТЗ 8.4, стратифицированный бутстреп с группировкой по исследованию, подбор
порога по F1. `scripts/07_spine_rules.py` переведён на него.

**Что осталось тебе: разметка бедра** (~80 изображений, 4 точки). Её

## 3. Правило укладки: не то, что было в плане

В плане стояло «касание маской нижнего края кадра». Признак **вырожден**:
маска касается нижнего и верхнего края у всех 99 исследований, у позитивов и
негативов одинаково. Если ты где-то на него закладывался — не закладывайся.

Работает другое: плотность **сбоку** от позвоночника в нижней трети кадра.
Нет гребней подвздошных костей в кадре — сбоку внизу пусто. Зазор между
классами вчетверо (0.018 против 0.075), специфичность 1.000 на 93 негативах,
решение не меняется ни на одном из 36 сочетаний параметров.

Два позитива из шести правило не ловит: у них гребни в кадре, а нарушена
вторая половина критерия ТЗ (не попала половина тела Th12). Шесть признаков
верха кадра их не отделяют — один из двух лежит в середине распределения
негативов. Если у твоего классификатора артефактов найдётся эмбеддинг,
который их разделяет, скажи: на двух примерах правило не строится, но
проверить гипотезу стоит.

## 4. Что тебе считать метрическим модулем

Ничего нового по сравнению с договорённостью 17-го, но теперь есть на чём:

* `reports/spine_rules.csv` — по каждому размеченному позвоночнику: метки,
  предсказания обоих правил, угол, латеральная плотность, признаки кривизны;
* `reports/batch_diagnostics_train.csv` — то же самое из сквозного прогона,
  плюс все служебные колонки конвейера. Сверка одного с другим даёт
  0 расхождений на 99 строках — если после твоих правок разойдётся, ищи
  разницу в параметрах.

Метрики по полной выборке — основные; тот же расчёт без исследований с
находками вне перечня 2.3 — диагностический. Для укладки разницы нет
(сколиоз на неё не влияет), для оси F1 растёт с 0.50 до 0.61.

## 6. Если будешь делать CNN всё-таки

Не надо, пока не появятся данные. Но если возьмёшься, сравнивать надо не с
нулём, а с бейзлайном: `python scripts/08_train_artifact.py` печатает
таблицу вариантов и кладёт out-of-fold предсказания в
`reports/artifact_oof.csv`. Условия сравнения: те же фолды, порог из
обучающих фолдов, метрика F1. Гребневой признак (`ridge` в
`reports/artifact_features.csv`) даёт ROC-AUC 0.879 — выше, чем у
принятого решения; если твоя модель не бьёт 0.72 по F1 и 0.88 по AUC, она
не нужна.
