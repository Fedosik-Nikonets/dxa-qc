## 5. Ключ сопоставления

Идентификатор исследования в разметке — **имя каталога верхнего уровня** (`2.25.…`).
Совпадение с каталогами: 100 из 100.

StudyInstanceUID (0020,000D) внутри файлов — другой (`1.2.643.5.1.13.13.12.2.77.…`),
пересечение с разметкой: **0**.

**Следствие.** Загрузчик и отчёт используют путь как ключ исследования. В колонку `study_uid`
выходной таблицы пишем тег из DICOM (как требует ТЗ 2.5), но сопоставление с истиной ведём по пути.

## 6. Масштаб изображения

| Тег | Присутствует |
|---|---|
| PixelSpacing (0028,0030) | нет ни в одном файле |
| ImagerPixelSpacing (0018,1164) | нет ни в одном файле |
| Exposed Area (0040,0303) | 448 из 499, ненулевые |

Exposed Area / размер кадра даёт 0.60–0.61 мм/пиксель в 54% случаев — это совпадает с паспортным
размером пикселя Lunar Prodigy Advance. В остальных случаях получается 1.7–2.5 мм/пиксель, что
для кропа тазобедренного сустава физически невозможно: тег описывает поле сканирования,
а сохранённое изображение — вырезанный из него фрагмент.

**Решение.** Константа 0.6 мм/пиксель с проверкой через Exposed Area (реализовано в
`dicom_io._spacing_from_exposed_area`). Правила ТЗ «3 см сверху/снизу, 2 см сбоку» переводятся
в 50 и 33 пикселя соответственно.

**Это вопрос организатору.** Резервный вариант, если константа неверна: относительные единицы —
отступ как доля от поперечного размера кости.

## 7. Анатомическая область не размечена в тегах

BodyPartExamined (0018,0015), ViewPosition (0018,5101), Laterality (0020,0060) присутствуют,
но **пустые во всех 499 файлах**. SeriesDescription — «Изображения DXA» / «DXA Images»,
без указания области. Роутер обязан работать только по пикселям.

## 8. Автоматическое разнесение меток по изображениям

Число уникальных изображений в исследовании в точности равно числу размеченных областей:

| Размечено областей | Исследований | Уникальных изображений |
|---|---|---|
| 1 (только позвоночник) | 22 | 1 |
| 2 | 6 | 2 |
| 3 | 72 | 3 |

Это превращает задачу «какая область на снимке» в паросочетание внутри исследования.
Реализовано в `02_build_dataset.py`:

1. самое симметричное изображение (корреляция с зеркальным отражением) — позвоночник;
2. оставшиеся два разделяются по латеральности: смещение таза в верхней трети кадра
   относительно диафиза в нижней.

Результат: 245 изображений из 252 размечены уверенно (spine 99, femur_left 76, femur_right 72),
**7 изображений в 3 исследованиях** помечены `region_confident=False` и требуют проверки глазами.

Направление латеральности откалибровано по файлам из «Для теста.zip» с явными именами
(`CR000000_ППОБ.dcm`, `CR000001_ЛПОБ.dcm`, `CR000000_ПОП.dcm`):

| Файл | sym | lat_score |
|---|---|---|
| ПОП (позвоночник) | 0.819 | +11.8 |
| ППОБ (правое бедро) | −0.020 | +75.2 |
| ЛПОБ (левое бедро) | 0.224 | −56.8 |

Проверка на обучающем наборе: `femur_left` максимум −10.4, `femur_right` минимум +47.8.
**Разделение по знаку без единой ошибки.**

Ручная разметка области не нужна.

## 9. Расхождения в метках эксперта

Агрегат «Итог» не равен OR по компонентам в 3 исследованиях из 100:

| Исследование | Компоненты | Итог | Комментарий |
|---|---|---|---|
| 2.25.339027809107632348165171236474821772940 | 0, 0, 0 | 1 | сколиоз |
| 2.25.52532476139575422857225834315571570912 | 0, 0, 0 | 1 | Сколиоз, не верная разметка |
| 2.25.127126130998341190348103034690069487890 | 0, 1, 0 | 0 | перелом |

Ещё одно исследование (`2.25.129239680100193368599713239115902740628`, 1 файл) не размечено вообще.

Комментарии эксперта содержат находки вне перечня ТЗ 2.3: сколиоз (13), эндопротез ТБС (2),
перелом (1), люмбализация L6 (1), «требует внимания» (2).

**Следствие.** Нужно решение по таксономии: предложение — отдельный флаг `OUT_OF_SCOPE_FINDING`,
не влияющий на `quality_class`, но попадающий в `violation_type`. Материал для слайда по критерию 8.1.

## 10. Разбиение выборки

PatientID (0010,0020) = «Anonymized» во всех файлах. Повторные визиты одного пациента
неотличимы. Единица разбиения — исследование, а не пациент. Это ограничение, его надо
указать в README и на питче.

При 100 исследованиях и 7 позитивах в самом редком классе одиночный сплит 80/20 непригоден:
доверительный интервал будет шире полезного диапазона. Используем 5-fold CV, фолд 0
дополнительно помечен как быстрый holdout.

## 11. Расхождение с ТЗ

ТЗ 2.4: «Одно исследование может включать одно или несколько изображений/серий (не более 3)».
Фактически до 29 файлов в исследовании. После дедупликации ограничение выполняется (максимум 3),
но загрузчик и пакетная обработка не должны на него опираться.
