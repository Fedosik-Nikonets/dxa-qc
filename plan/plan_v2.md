# План v2 — после разведки данных (15 сентября)

Заменяет план от 15 сентября. Причина пересмотра: в наборе нет экспертной ROI-разметки,
половина файлов — дубликаты, а по четырём из пяти классов нарушений позитивов меньше 20.
Это делает нежизнеспособной исходную ставку на обучение по ключевым точкам.

---

## 1. Что изменилось: пять решений

**Р1. Геометрия вперёд, обучение вторым слоем.**
Позитивов по классам: укладка позвоночника — 6, наклон оси — 10, артефакты — 17,
ротация бедра — 36 (17 R + 19 L), охват ROI — **7** (3 R + 4 L). На 6–10 позитивах
CNN не обучается ни в каком виде. Зато три из пяти правил ТЗ вычисляются
детерминированно из маски кости, вообще без разметки:

| Нарушение | Как определяем | Разметка нужна? |
|---|---|---|
| Наклон оси > 5° | главная ось бинарной маски позвоночника (PCA/моменты), угол к вертикали | нет |
| Охват ROI (3 см / 2 см) | bbox кости → отступы до краёв кадра → мм через масштаб | нет |
| Укладка позвоночника | касание маской нижнего края + анализ верхней границы | частично |
| Ротация бедра | профиль медиального контура + классификатор | да, для валидации |
| Артефакты / инородные тела | классификатор + Grad-CAM | нет (17 позитивов хватает) |

Размеченные 6–10 позитивов используются **для калибровки порога и валидации**,
а не для обучения. Это защитимая позиция на питче и прямой ответ на критерий 8.1
(«работа с дисбалансом классов»).

**Р2. Дедупликация обязательна и делается до всего остального.**
499 файлов → 252 уникальных изображения. В одном исследовании 29 файлов и 3 уникальных.
Всё — обучение, метрики, сплит — работает по дедуплицированной таблице.
На инференсе дубликаты обрабатываются как обычные строки отчёта (ТЗ требует строку на изображение).

**Р3. Метки спускаются на изображения автоматически.**
После дедупликации число уникальных изображений в исследовании в точности равно числу
размеченных областей (1 / 2 / 3). Соответствие «изображение ↔ область» — паросочетание.
Реализовано, 245 из 252 изображений размечены уверенно, 7 в 3 исследованиях — на ручную проверку.
Сторона бедра калибрована по именам файлов из «Для теста.zip» и разделяется без ошибок.
**Ручная разметка областей не нужна.**

**Р4. Ручная разметка — минимальная и только для бедра.**
Размечаем ~80 бедренных изображений: большой вертел, малый вертел, шейка, седалищная кость.
Цель — не обучение, а проверка гипотезы о профиле контура и калибровка порогов
пере-/недоротации. Позвоночник не размечаем вообще: ось берётся из маски.
Бюджет — 1 день одного человека вместо 3 дней двоих.

**Р5. Контейнер CPU-only.**
Изображения 280×300, 8 бит, ~2.5 на исследование. Модель — resnet18/efficientnet-b0 на 256 px.
Инференс одного исследования на CPU — доли секунды при лимите 3 минуты.
Базовый образ `python:3.11-slim` + torch CPU-wheel вместо `nvidia/cuda`: образ ~1.5 ГБ вместо ~8 ГБ,
сборка минуты вместо десятков минут, на техэкспертизе нечему ломаться в CUDA-рантайме.
GPU используется только при обучении, локально.

## 2. Что режем окончательно

Оставляем из допфункционала (ТЗ 2.6) только **overlay-серию** — контур кости, ось позвоночника,
рамка ROI, тепловая карта артефакта. Дёшево (маска уже есть), сильно играет на демо и на критерий 8.3.

Вычёркиваем: DICOM SR, автокоррекцию разметки, веб-интерфейс, детектор артефактов
как object detection, любые keypoint-модели для позвоночника.

## 4. Календарь

### 16 сентября, вт — фундамент

**Фёдор.** Загрузчик: MONOCHROME1, сжатые TransferSyntax, multi-frame, VOI LUT, отсутствие
масштаба, 16 бит. В обучающем наборе все 499 файлов однотипны (Implicit VR LE, 8 бит,
MONOCHROME2, несжатые) — на закрытом наборе это не гарантировано, покрываем синтетикой.
Юнит-тесты на каждый случай. Сегментация кости: порог + морфология + крупнейшая компонента,
визуальная проверка на всех 252 изображениях.

**Напарник.** Роутер на 3 класса (spine / femur_left / femur_right) на автоматически
размеченных 245 изображениях. Задача лёгкая, ожидаем > 0.98. Метрический модуль:
sensitivity, specificity, balanced accuracy, F1, ROC-AUC, PR-AUC, macro-F1, бутстреп-ДИ 95%.

**Вместе, вечером (1 час).** Финализировать таксономию: 5 обязательных лейблов ТЗ + решение
по сколиозу, перелому и эндопротезу (13 + 1 + 2 случая в комментариях эксперта, в перечень 2.3
не входят, но в трёх исследованиях повлияли на «Итог»). Предложение: отдельный флаг
`OUT_OF_SCOPE_FINDING`, не влияющий на `quality_class`, но попадающий в `violation_type`.
Прогнать `03_make_split.py`, зафиксировать сплит, закоммитить, больше не трогать.

**Сдать к вечеру:** `dataset_images.csv` проверен глазами (7 спорных), `split.csv` в репозитории.

### 17 сентября, ср — сквозной скелет

**Фёдор.** `python -m dxa_qc.batch --input dir --output result.xlsx` выдаёт валидную таблицу
по ТЗ 2.5 с заглушками вместо предсказаний. Ключ исследования — имя каталога, а не
StudyInstanceUID из тегов (они не совпадают). С этого дня всегда есть что сдать.
Обработка ошибок: каждая строка либо Success, либо Failure с текстом.

**Напарник.** Классификатор артефактов позвоночника (17 позитивов, 99 изображений):
efficientnet-b0, 5-fold, focal loss, Grad-CAM. Это самый «обучаемый» класс, делаем первым.

### 18 сентября, чт — геометрия позвоночника

**Фёдор.** Ось позвоночника из маски: главная компонента, угол к вертикали, порог 5°.
Валидация на 10 размеченных позитивах и 89 негативах — это и есть основная метрика по классу.
Правило укладки: касается ли маска нижнего края кадра, видна ли верхняя граница поля.

**Напарник.** Разметка бедра (~80 изображений, 4 точки).

**Контрольная точка:** если угол по маске не отделяет 10 позитивов от негативов
(ожидаем AUC > 0.9), переходим на резервный вариант — регрессия угла маленькой CNN по псевдо-меткам
от маски. Решение принимается в тот же вечер.

### 19–20 сентября, пт–сб — позвоночник закрыт, бедро начато

**Фёдор.** Геометрия бедра: bbox кости, отступы до краёв кадра в миллиметрах,
правила 30 мм / 20 мм. Масштаб — 0.6 мм/пиксель (паспорт GE Lunar Prodigy Advance)
с проверкой через (0040,0303) Exposed Area. Валидация на 7 позитивах по охвату ROI.

**Напарник.** Профиль медиального контура бедра: отклонение реального контура от сглаженной
аппроксимации как непрерывный признак. Малое отклонение — переротация, избыточное — недоротация.
Калибровка порогов по 36 позитивам.

### 21 сентября, вс — КОНТРОЛЬНАЯ ТОЧКА

К вечеру должны работать: роутер, все три правила позвоночника, оба правила бедра,
сквозной прогон с реальными предсказаниями, метрики на 5 фолдах.

Если не закрыто — режем в этот же вечер, по порядку: overlay-серия, затем правило укладки
позвоночника (6 позитивов, самое слабое), затем охват ROI бедра (7 позитивов).
Каждое сокращение честно описывается в разделе «Ограничения» README и на слайде.

### 22–23 сентября, пн–вт — мультилейбл и калибровка

Мультилейбл-голова на конкатенации эмбеддинга изображения и геометрических признаков
(угол, отступы в мм, отклонение контура, площадь маски). Калибровка порогов по F1 —
приоритетная метрика по ТЗ 8.4. Работа с дисбалансом: взвешивание классов + oversampling.

Аугментации: повороты ломают критерий наклона оси, кропы ломают критерий отступов.
Только яркость, контраст, шум, лёгкий эластик. Это сознательное решение, его надо
уметь объяснить на питче.

Overlay-серия: контур кости, ось, рамка ROI, Grad-CAM артефакта. Отдельный DICOM
или PNG в zip-архиве.

### 24 сентября, ср — сервис и контейнер

FastAPI: `/predict`, `/batch`, `/health`. CLI-обёртка. `build.sh` + `run.sh`.
Веса внутри образа. Все версии зафиксированы (`requirements.txt` уже готов).

**Обязательно:** `docker run --network none` и полный прогон. Любой
`timm.create_model(pretrained=True)` или `torch.hub` в рантайме — ноль на техэкспертизе.
Это самый частый способ проиграть.

### 25 сентября, чт — устойчивость

Стресс-тест: битый DICOM, не-DICOM файл с расширением .dcm, пустой архив, неизвестная
анатомическая область, 16-битное изображение, MONOCHROME1, файл без Exposed Area,
изображение 1×1, исследование из 29 файлов. На каждый — строка с `processing_status=Failure`,
ни одного вылета.

Воспроизводимость: два прогона дают побайтово одинаковый xlsx.
`torch.use_deterministic_algorithms(True)`, фиксация seed, сортировка файлов.

Замер времени на CPU и GPU — в презентации нужна минимальная конфигурация (ТЗ 3.1).

### 26 сентября, пт — анализ ошибок и метрики

Таблица FP/FN по каждому классу с примерами изображений. Метрики с бутстреп-ДИ 95%
отдельно по областям и по типам нарушений. Сравнение вариантов: baseline-классификатор
на всю картинку против геометрии против гибрида — это слайд «сравнение вариантов модели» (ТЗ 4).

### 27 сентября, сб — документация. **ЗАМОРОЗКА КОДА**

развёртыванию, описание процедуры обучения. Раздел «Ограничения» пишется честно:
редкие классы, отсутствие масштаба в тегах, разбиение по исследованию, а не по пациенту.

Вечером код замораживается.

### 28–29 сентября, вс–пн — буфер

Финальная проверка на чистой машине, отправка. Только критические правки.

## 5. Риски

| Риск | Вероятность | Что делаем |
|---|---|---|
| Геометрия не отделяет 6–10 позитивов | средняя | контрольная точка 18-го, резервный CNN на псевдо-метках |
| Масштаб 0.6 мм/пиксель неверен | средняя | правило охвата ROI переводится в относительные единицы (доля от размера кости), теряется буквальное соответствие ТЗ, но метрика сохраняется |
| Закрытый набор содержит другое оборудование | низкая | загрузчик покрывает краевые случаи, при неизвестной области — Failure с текстом, а не вылет |
| Разбиение по исследованию, а не по пациенту | реализовался | PatientID анонимизирован, повторные визиты неотличимы. Описано в ограничениях |
| Промежуточная сдача по ТЗ 7.1 объявлена на ~22 сентября | неизвестно | **спросить организатора до 17-го**. Если да — бедро уезжает за её границу, сдаём MVP по позвоночнику |
